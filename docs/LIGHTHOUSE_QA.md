# Lighthouse verification — 2026-11-17

Actual Lighthouse **13.6.0** CLI reports, Chrome **157**, Windows. The target was
the local **production build** at `http://127.0.0.1:5001`, not Vite development.
Each home-page final profile ran three times sequentially in separate headless
Chrome sessions, with Lighthouse's default storage reset. No network requests,
audit categories, CSP checks or indexing checks were suppressed.

Mobile used the default simulated 150 ms RTT, approximately 1.6 Mbps and 4× CPU
slowdown. Desktop used `--preset=desktop`: 40 ms RTT, 10,240 Kbps and 1× CPU.
These are lab simulations on localhost, not field Core Web Vitals or measurements
of a deployed site's real hosting/CDN/mobile network.

## Findings and fixes

1. Lighthouse caught a real **CSP error**: the Google Fonts stylesheet's inline
   `onload` handler violated Helmet's `script-src-attr 'none'`. The stylesheet
   remained in print media. Earlier browser checks did not reveal this issue.
   Replaced that mechanism with self-hosted variable WOFF2 subsets, bundled CSS,
   a preload for the primary Georgian font and `font-display: optional`. Font
   requests now stay on the same origin and use the existing immutable asset
   cache. OFL licenses and source/checksum records are in
   `client/public/font-licenses`. **CSP was not weakened.** The final console and
   Issues-panel audits pass; best practices rose from 92 to 100.
2. Lighthouse reported approximately **55 KiB unused JS** on the initial page.
   The header/footer pulled full Zod form validation into startup through pricing
   navigation helpers. Separated the lightweight calculator context from the
   full form/API schemas; full validation still runs for forms and on the server.
   Added boundary/parity coverage to guard the two validation paths. Initial
   gzip JS fell from **164,941 to 150,161 bytes**; raw UTF-8 JS fell from **565,800
   to 504,578 bytes**. Demo pricing, selection URLs and saved inquiries are
   unchanged. Final unused-JS diagnostics fell to approximately 42 KiB.
3. SEO's only failed scored audit is **`is-crawlable`**, caused by the intentional
   `noindex` meta and X-Robots-Tag on local/test pages. It was not removed merely
   to improve a score. A separate loopback-only process on port 5003 used the
   reserved `https://assist.example` origin and `INDEXING_ENABLED=true` to verify
   the existing publishing configuration. SEO-only Lighthouse runs scored
   **100 on mobile and desktop**. This was a technical configuration test, not
   public publication, a confirmed company domain or actual search indexing.
   The temporary process was stopped; the normal port 5001 remains noindex.

Remaining diagnostics include shared CSS unused on a particular page (about
13 KiB, estimated 20 ms) and shared UI/translation JavaScript (about 42 KiB,
estimated 0 ms savings in the representative run). They do not indicate broken
pages; removing shared styles indiscriminately would affect other routes.
One initial baseline back/forward-cache diagnostic reported critical machine
memory pressure and marked it not actionable.
