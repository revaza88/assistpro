Node 24+ და დაყენებული npm დამოკიდებულებები. სამუშაო საქაღალდე `D:\Assist\assistpro`, ზემოთ მითითებული სამუშაო განშტოება.

```powershell
npm run check
npm test
npm run build
$env:NODE_ENV='production'
$env:HOST='127.0.0.1'
$env:PORT='5017'
$env:SITE_URL='https://assist.ge'
$env:INTAKE_MODE='disabled'
$env:INDEXING_ENABLED='false'
$env:LOG_TO_FILE='false'
npm start
```

გახსენით **http://127.0.0.1:5017/**, `/en/`, `/ru/` და შესაბამისი სერვისები. canonical განზრახ სამომავლო საჯარო URL-ზე მიუთითებს; ლოკალური preview ინდექსირებადი არ არის. მეორე ტერმინალში:

```powershell
npm run audit:seo -- http://127.0.0.1:5017 https://assist.ge
```

გაშვების სიმულაცია შესრულდა ცალკე loopback `5018`-ზე, `SITE_URL=https://assist.example`, `INDEXING_ENABLED=true`, `INTAKE_MODE=disabled`. ეს რეჟიმი წარმოებაში არ გადაიტანოთ მიღების გარეშე. სიმულაციის შემოწმების ბრძანება:

```powershell
npm run audit:seo -- http://127.0.0.1:5018 https://assist.example --indexing
node --import tsx scripts/audit-web.ts http://127.0.0.1:5018 --indexing
```

## კონკრეტულად რა უნდა დამტკიცდეს გაშვებამდე

1. KA/EN/RU ახალი სამი სერვისის ტექსტი, მოცულობის გამიჯვნა, კომპანიის საჯარო იდენტობა და აუდიტის აღწერის შესაბამისობა რეალურ უფლებამოსილებასთან.
2. ენობრივი URL სქემა (KA ძველი / EN `/en/` / RU `/ru/`), ქართული x-default და sitemap-ის საბოლოო გვერდების სია. გადაწყდეს ზემოთ დარჩენილი სამი მეორეული სერვისის სარედაქციო კარიბჭე.
3. გამოქვეყნების ცალკე ნებართვა: კოდის review/ინტეგრაცია და ჯერ `INDEXING_ENABLED=false`-ით წარმოებაში გადატანა. ეს დავალება ამის ნებართვა არ არის.
4. წარმოებაში საბოლოო მრავალენოვანი მომხმარებლის გზის ბრაუზერული შემოწმება და სწორი build identity. მიმდინარე ჰოსტინგის `release.json`-ის უცნობი Git metadata ცალკე მოსაგვარებელია; აქტივის hash-ით დადასტურება source commit-ს არ უდრის.
5. **ცალკე თანხმობა ინდექსაციის ჩართვაზე:** ზუსტად `SITE_URL=https://assist.ge`, `INDEXING_ENABLED=true`, საიტისა და პროქსის noindex-ის მოხსნა მხოლოდ შეთანხმებულ გვერდებზე; Googlebot/OAI-SearchBot გაშვების წესები. `INTAKE_MODE=disabled` უცვლელი რჩება; GPTBot-ის პოლიტიკა უცვლელი რჩება.
6. გადატანის შემდეგ რეალური HTTP/HTML აუდიტი: 200 sitemap/კანონიკური URL-ები, HTML+header index/noindex შესაბამისობა, 404/301, CSP, hreflang ორმხრივობა, JS-ის გარეშე შინაარსი, მობილური, და robots/WAF-ის ბოტებთან ქცევა. რეალური ბოტის დასადგენად გამოიყენება ოფიციალური IP/იდენტიფიკაციის მითითებები და არა მხოლოდ User-Agent.
7. Search Console საკუთრების წვდომა/დამოწმება და sitemap-ის გაგზავნის ცალკე თანხმობა. ამ სამუშაოში არც ანგარიშზე შესვლა და არც გაგზავნა არ შესრულებულა.

## უკან დაბრუნება

თუ გაშვების შემდეგ ინდექსაციის პრობლემა აღმოჩნდა: დაუყოვნებლივ `INDEXING_ENABLED=false` და შეთანხმებული პროცესის restart; ამით HTML/HTTP ისევ noindex და sitemap ისევ 503 იქნება. ამის შემდეგ წინასწარ შენახული build/შემოწმებული Git revision აღდგეს ჩვეულებრივი revert/redeploy პროცესით — force-push/reset --hard არ არის საჭირო. ახალი URL-ების უკვე აღმოჩენის შემდეგ შეინარჩუნეთ შესაბამისი 301-ები; ნუ წაშლით ენობრივ გვერდებს დაუგეგმავად. ბაზის მიგრაცია ან მონაცემთა დაბრუნება ამ ცვლილებას არ სჭირდება. სხვა სერვისის/პროქსის cache ცალკე შესამოწმებელია.
