# სხვა სამუშაო გარემოდან AssistPro-ს გაგრძელება

განახლებულია: 2026-11-27. ძირითადი რეპოზიტორია:
https://github.com/revaza88/assistpro

ეს ინსტრუქცია გამოიყენება სხვა Codex პროექტიდან, კომპიუტერიდან ან checkout-იდან.
ფაილის წაკითხვა წვდომას ავტომატურად არ ანიჭებს: საჭიროა GitHub-ის შესაბამისი
უფლება და განთავსებისთვის Dokploy-ის ანგარიში ან API წვდომა.

## პირველი ნაბიჯები

1. გამოიყენეთ ამავე რეპოზიტორიის არსებული checkout ან ჩამოტვირთეთ იგი.
2. წაიკითხეთ `AGENTS.md`, `docs/SITES_ALIGNMENT.md` და
   `deploy/ASSIST_INFRASTRUCTURE.md`. ძველი ანგარიშები თარიღით შეადარეთ;
   ახალი ინფრასტრუქტურა არ ნიშნავს, რომ პორტალი/AI/რეალური მიღება დასრულებულია.
3. შეამოწმეთ სამუშაო ფაილები და remote; შეინარჩუნეთ დაუკომიტებელი ცვლილებები.
4. ახალი სამუშაო დაიწყეთ განახლებულ `origin/main`-ზე დაფუძნებულ `codex/` ბრენჩში.

```sh
git remote -v
git status --short --branch
git fetch origin
# მხოლოდ სუფთა checkout-ში; შეცვალეთ ბრენჩის სახელი ამოცანის მიხედვით
git switch -c codex/assist-next-change origin/main
npm ci
```

Node.js 24+ და npm 9+ გამოიყენეთ. `.env` ფაილს Express ავტომატურად არ ტვირთავს;
ცვლადები პროცესის გარემოში ან შესაბამისი launcher-ით უნდა მიეწოდოს.

## ცვლილებების ორი დამოუკიდებელი გზა

**აპლიკაცია:** React/Vite + Express კოდისთვის გაუშვით `npm run check`, `npm test`,
`npm run build` და შეცვლილი ფუნქციის მიზნობრივი შემოწმება. ატვირთეთ სამუშაო
ბრენჩი და გახსენით PR. `main`-ზე push/merge საჯარო საიტის ავტომატურ განთავსებას
იწვევს; დოკუმენტაციის ატვირთვა და production-ის გამოშვება ცალკე მოქმედებებია.

**ინფრასტრუქტურა:** შეცვალეთ `deploy/assist-infrastructure.compose.yaml`,
შეამოწმეთ `docker compose -f deploy/assist-infrastructure.compose.yaml config --quiet`
Docker-ის მქონე გარემოში და შეადარეთ Dokploy-ის მიმდინარე Raw კონფიგურაციას.
შემოწმებულ YAML-ს არსებული `assist-infrastructure` სერვისის Raw რედაქტორში
ჩასმა, Save და Deploy სჭირდება. GitHub-ზე YAML-ის ცვლილება ამ სერვისს ავტომატურად
არ განაახლებს. Save-ის შემდეგ გადაამოწმეთ შენახული ტექსტი: რედაქტორში ჩვეულებრივი
პროგრამული setValue ამ სესიაში ცვლილებას არ ინახავდა; რეალური paste მუშაობდა.

არ შექმნათ ახალი Compose პროექტი და არ გაუშვათ დამოუკიდებელი `compose up` სხვა
სახელით. შეინარჩუნეთ არსებული volume-ები და სერვერის secret ფაილი. ბაზა ახლა
იზოლირებულ შიდა ქსელშია; აპლიკაციის დაკავშირება მოითხოვს კოდის, როლებისა და
ქსელის შეთანხმებულ ცვლილებას. მხოლოდ `DATABASE_URL`-ის დამატება საკმარისი არ არის.
